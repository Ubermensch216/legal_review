## 3. 기본분석 / 심화분석

| | 기본분석 | 심화분석 |
|---|---|---|
| 판단 대상 | 결론을 좌우하는 요건만. 조문 분해에 실패한 골격 요건은 판단하지 않음 | 모든 요건 |
| 출력 | 요건별 짧은 판단(이유 70자) | 서술 260자, 판례 대비, 반대 논리 |
| 근거 대조 | 판단을 낸 요건마다 가장 가까운 근거 소수, 뒷받침되면 중단 | 모든 주장·근거 쌍 |
| 목록 선별 | 경계 후보를 모델에 묻지 않고 본문 확인 대상으로 유지 | 경계 후보를 모델에 질의 |
| 수정 조문 | 만들지 않음 | 만듦 |
| 표시 | 항상 "검토 완료"가 아님, 제목 "(기본분석)", 대조 건수 표시 | 종전과 동일 |

- 수준을 지정하지 않거나 알 수 없는 값이면 심화분석으로 처리한다(검증이 조용히 줄어드는 것을 막기 위함).
- 대조하지 않은 주장은 "미확인"과 구별해 `NOT_CHECKED`로 기록하고, 공식 출처·시행 여부만 확인한 근거는 `SOURCE_ONLY`로 표시한다. "검증됨"으로 올리지 않는다.
- 기본분석 결과에서 심화분석으로 이어가면 사실·쟁점·수집 근거를 재사용하고 판단과 검증만 전체 범위로 다시 한다. 보관된 산출물은 서버 메모리에 3시간만 남는다.

## 4. 문서 판단 방식과 그 검증

모델에게 "법 규정을 충족하는가"를 묻는 대신 "문서가 이 규정을 지키는가"를 묻고, 문서 원문 문장을 40자 이내로 글자 그대로 인용하게 한다. 인용이 문서에 없으면 판단을 "사실 추가 확인 필요"로 낮춘다. 결론은 `위반 소지`, `위반 사항 미발견`, `추가 확인 필요` 중 하나이며 위법 확정이 아니다.

- ⑤(로컬): 모델이 낸 "문서가 규정을 지킨다" 답이 전부 법령 문구라 문서 인용이 없어 모두 강등됐다. 위반으로 인용된 요건은 37개 중 0개였다. 거짓 결론은 막았지만 쓸모 있는 지적도 없었다.
- ⑥(외부): 문서 조항을 정확히 인용한 위반 지적이 나왔다.
  - 제31조 "서면 통지를 갈음하여 구두 또는 사내 메신저 통보로 할 수 있다"
  - 제31조 "청문 절차 없이 즉시 해고할 수 있다"
  - 제41조 "불이익 변경의 경우에도 별도 동의 없이 시행할 수 있다"
  - 제23조 연장근로 1주 68시간
- 추출된 사실도 로컬 2개 대비 외부 24개였다.

### 외부 모델 시험에서 발견해 고친 문제

⑥에서 위반 지적이 있었던 쟁점 I2·I3·I4 모두 결론이 "판단 유보"로 나왔다. 원인과 수정은 다음과 같다.

1. 선결 쟁점: 모델이 "개별 조항 내용이 확인되지 않아 판단할 수 있는가?"라는 막연한 쟁점(I1)을 세웠고, I1이 풀리지 않아 후속 쟁점의 결론이 유보됐다. 문서 원문 인용으로 확인된 위반 소지는 선결 쟁점이 미해결이어도 유지하고, "위반 없음"을 확정할 때만 선결 쟁점이 막도록 바꿨다.
2. 규정 근거 검증: I4는 규정 근거 대응이 확인되지 않아 낮춰졌다. 요건은 조문을 분해해 만든 것이므로 문서 판단의 규정 근거에 요건의 출처 조문을 포함하도록 바꿨다.

저장된 ⑥ 결과를 새 규칙으로 다시 계산하면 I2·I3·I4·I5가 모두 "위반 소지"가 된다. 단, 수정 2(규정 근거 검증)는 모델 호출이 필요한 부분이라 아직 확인하지 못했다.

## 5. 외부 LLM 사용 방식

설정에서 내부 LLM만 / 내부+외부 병용 / 외부 LLM만을 고른다.

| 확인 항목 | 방법 | 결과 |
|---|---|---|
| 승인 없는 외부 전송 차단 | 단위·API 시험, 승인 없이 `/workbench` 호출 | 외부로 나가는 요청 0건, 409 응답 |
| 승인은 전송 내용의 해시에 묶임 | 해시를 바꾸거나 승인 뒤 입력을 바꾼 요청 | 모두 거절 |
| 비식별 | 주민번호·전화·이메일·계좌·주소·사업자번호·직함 붙은 이름 | 전송문에서 제거됨, 돌아온 답변은 원래 값으로 복원 |
| 비식별 한계 | 패턴 기반이라 익명화 보증이 아니다 | 전송 전 확인 창에서 사용자가 직접 검토하고 가릴 단어를 추가 |
| 전송 기록 | `data/cache/external-audit.jsonl` | 시각·제공자·승인 방식·해시·분량만 기록, 내용은 남기지 않음 |
| EXAONE 실제 호출(병용 재검토) | 가짜 개인정보가 든 시험 쟁점 | 56초, 형식대로 응답, 결론은 코드가 재계산(판단 유보 → 요건 불충족) |
| 외부 LLM만(⑥) | 가상 샘플 문서를 비식별 후 전송 | 남은 식별정보 0건, 전송 기록 48건 |

병용 모드는 로컬 파이프라인이 끝난 뒤 풀지 못한 쟁점(최대 3개)만 제안하고, 쟁점마다 사용자가 비식별 전송 내용을 확인·승인해야 전송한다. 외부 모델은 같은 판단 단계를 다시 실행할 뿐이고 결론은 코드가 요건 판단으로 다시 계산하며, 외부 답변의 근거 확인은 로컬 모델이 한다. 반영된 쟁점은 화면에 "외부 LLM 판단"으로 표시된다.

## 6. 자동 테스트와 화면 확인

- 전체 362건 중 359건 통과. 실패 3건(`reasoningStages`·`elements`의 분할 추출 3건)은 변경을 되돌린 상태에서도 똑같이 실패하는 이전부터 있던 건이며, 이번 변경과 무관하다.
- 이번에 추가한 시험은 기본/심화 분기, 문서 조항 연결, 제한 검증, 원문 인용 검증, 결론 계산, 비식별·복원, 외부 재검토, 승인 API, 정답셋 채점이다.
- 화면(브라우저): 설정의 3가지 사용 방식 전환, 외부 전송 확인 창(가려진 내용 표시·취소 시 검토 미시작), 분석 수준 선택과 실행 버튼 이름, 기본분석 결과 안내와 만료 세션 처리, 1280px 폭 배치를 확인했다.

## 7. 한계와 미검증

- 사례 01 한 건을 한 번씩만 측정했다. 모델 출력이 매번 달라 쟁점 목록도 측정마다 다르다. 사례 02~05는 최신 코드로 재지 않았다.
- 심화분석을 최신 코드(문서 판단 방식 포함)로 재측정하지 않았다. 약 1시간이 걸린다.
- 외부 모델이 더 빠르지는 않았다. 호출당 출력이 약 1,900토큰(추론 토큰 포함)이라 기본분석이 39분 걸렸다.
- 쟁점 정리 품질이 남은 약점이다. 막연한 쟁점이 생기고, 정답셋의 "경업금지·위약벌" 쟁점은 로컬·외부 모두 놓쳤다.
- 근거 재현율은 44~56%로, 정답셋 기대 조문 중 제20·54·60조 등이 계속 빠진다.
- 문서 원문 인용 검증은 띄어쓰기 차이만 허용한다. 모델이 문장을 요약해 인용하면 판단이 낮춰져 위반을 놓칠 수 있다.
- 병용 모드의 쟁점별 재검토는 서버 메모리에 보관된 중간 산출물에 기댄다. 서버 재시작 후나 이력에서 불러온 검토에서는 쓸 수 없다.
- 정답셋은 전문가 검수가 필요하다. 이 문서의 점수를 법리 정확도로 읽지 않는다.

## 8. 재현 방법

```powershell
$env:BASELINE_PIPELINE='staged'; $env:BASELINE_CASES='01'; $env:BASELINE_DEPTH='BASIC'
node test/benchmark/pipelineBaseline.js
node test/benchmark/compareRuns.js <이전.json> <이후.json>
```

`BASELINE_DEPTH`를 비우거나 `DEEP`으로 두면 심화분석이다. 측정 결과 JSON에 판단 실행 쟁점 수, 쟁점-조문 연결, 사실 수, 정답셋 점수가 함께 기록된다.
