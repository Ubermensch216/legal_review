# 입력 예산과 장문 발췌 개선

2026-09-21. 법리 품질 평가는 별도이며 아래 결과는 입력 구성과 측정 경로에 대한 검증이다.

## 변경

- 시스템 지시문, 질의, 문서, 공식 근거를 포함한 최종 프롬프트에 대해 입력 예산을 검사한다. 출력 예약량과 여유 512토큰을 별도로 남긴다.
- 초과하면 문서·근거 예산을 줄여 다시 구성하고 생략 경고를 유지한다. 질의·필수 지시문만으로 한도를 넘으면 API를 호출하지 않고 실패를 표시한다. 질의를 몰래 자르지 않는다.
- 출력 예약량을 OpenAI/Anthropic/Gemini의 출력 제한 및 Ollama의 `num_predict`에 일치시킨다. Ollama의 `num_ctx`도 같은 컨텍스트 설정을 사용한다.
- `review.inputBudget`에 사전 추정, `review.tokenUsage`에 제공자 응답의 사용량을 구분해 저장한다. 사용량 누락은 0이 아니라 null이다. 잘린 출력에서도 제공자가 반환한 사용량을 보존한다.
- 문서 발췌 예산을 여러 조항에 배분한다. 긴 조항은 위험 키워드 또는 질의 일치 지점 주변을 최대 3개 구간으로 발췌한다. `inputCoverage.selectedClauses`에 조항과 조항 본문 기준 발췌 범위를 남긴다.
- 문서 분할에서 표준 가지 조문 번호 `제15조의2`를 보존한다.

## 설정

`LLM_CONTEXT_TOKENS`, `LLM_OUTPUT_TOKENS`는 서버의 운영 예산이다. 기본값은 클라우드 경로 32768/3500, Ollama 16384/8192이며 기존 `OLLAMA_NUM_CTX`, `OLLAMA_NUM_PREDICT` 설정을 이어받는다. 이는 모델 제조사가 보장한 최대 용량 목록이 아니므로 실제 선택 모델의 한도에 맞게 설정해야 한다.

`LLM_MODEL_BUDGETS`에는 정확한 `제공자:모델명`을 키로 한 JSON을 넣을 수 있다. 예: `{"ollama:my-local-model":{"contextTokens":16384,"outputTokens":4096}}`. 모델별 항목이 공통 환경변수보다 우선한다. 내부 함수의 명시적 `llmConfig.contextTokens/outputTokens`는 그보다 우선하며 HTTP 요청에 예산 변경 입력은 추가하지 않았다.

추정 방식은 UTF-8 바이트 수 + 256이다. 한글을 영문과 같은 문자/토큰 비율로 계산하지 않기 위한 보수적 대용치이며 **모든 모델의 토큰 수 상한을 보장하거나 정확히 세는 방법이 아니다**. `exact:false`로 표시한다. 모델별 토크나이저 또는 제공자 사전 계수 API의 연결과 실제 계수 오차 평가는 여전히 남아 있다.

## 평가 결과

- 회귀 테스트 56개 통과. 실제 프롬프트·출력 한도, 모델별 설정, 과대 질의의 호출 차단, 제공자별 사용량 매핑, 잘린 출력, 가지 조문과 후반 위험 문구를 검증했다.
- `node test/benchmark/contextRecall.js`는 6종 합성 문서 × 2개 예산(1500/4500자)을 평가한다. [결과 JSON](context-recall-2026-09-21.json)에 성공과 실패를 모두 기록했다.
- 표식 18개 중 16개를 회수했다. 같은 예산의 단순 앞부분 발췌는 2개를 회수했다. 이는 의도적으로 배치한 표식의 회수 건수이며 제품 법률 정확도, 실제 사용자 문서 회수율, 이전 전체 구현 대비 개선율이 아니다.
- 키워드가 없는 말미 조건 대조군은 두 예산에서 모두 놓쳤다. 임베딩 검색, 의미 기반 쟁점 추출 및 문서 전수 검토는 구현하지 않았다. 부분 발췌 경고를 유지한다.
- 이번 작업에서는 유료 LLM 생성이나 실제 모델의 토큰 계수 측정을 수행하지 않았다. 사용량 매핑은 주입 응답으로 검증했다. 법령 API는 변경하지 않아 이전 통합 테스트를 반복하지 않았다.

## 참고한 공식 명세

- [OpenAI 토큰 계수](https://developers.openai.com/api/docs/guides/token-counting): 출력 사용량에는 비가시 토큰도 포함될 수 있다. 사전 추정과 제공자 사용량을 같은 값으로 취급하지 않는다.
- [Ollama Chat API](https://docs.ollama.com/api/chat): `prompt_eval_count`, `eval_count`를 응답에서 읽는다.
- [Gemini GenerateContent](https://ai.google.dev/api/generate-content): 응답의 사용량 메타데이터를 읽고 생각 토큰·전체 토큰을 별도로 보존한다.

전체 위임 관계·부칙 적용, 전문가 정답 기반 법리 평가, 브라우저·Word/한글 시각 검증, 외부 공개용 인증은 별도 잔여 과제다.
