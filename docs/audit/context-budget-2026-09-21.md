# 입력 예산과 장문 발췌 개선

> **과거 측정 기록:** 아래 예산·발췌 검증은 2026-09-21 당시 코드와 환경의 결과다. 현재 검토 경로와 2026-09-23 실모델 진단은 [현황 문서](../current-status.md)와 [비교 기록](pipeline-comparison-2026-09-23.md)을 따른다.

2026-09-21. 법리 품질 평가는 별도이며 아래 결과는 입력 구성과 측정 경로에 대한 검증이다.

## 변경

- 시스템 지시문, 질의, 문서, 공식 근거를 포함한 최종 프롬프트에 대해 입력 예산을 검사한다. 출력 예약량과 여유 512토큰을 별도로 남긴다.
- 초과하면 문서·근거 예산을 줄여 다시 구성하고 생략 경고를 유지한다. 질의·필수 지시문만으로 한도를 넘으면 API를 호출하지 않고 실패를 표시한다. 질의를 몰래 자르지 않는다.
- 출력 예약량을 OpenAI/Anthropic/Gemini의 출력 제한 및 Ollama의 `num_predict`에 일치시킨다. Ollama의 `num_ctx`도 같은 컨텍스트 설정을 사용한다.
- `review.inputBudget`에 사전 추정, `review.tokenUsage`에 제공자 응답의 사용량을 구분해 저장한다. 사용량 누락은 0이 아니라 null이다. 잘린 출력에서도 제공자가 반환한 사용량을 보존한다.
- 문서 발췌 예산을 여러 조항에 배분한다. 긴 조항은 위험 키워드·질의 일치·구조 표지 지점 주변을 최대 4개 구간으로 발췌한다. `inputCoverage.selectedClauses`에 조항과 조항 본문 기준 발췌 범위를 남긴다.
- 문서 분할에서 표준 가지 조문 번호 `제15조의2`를 보존한다.
- 입력 토큰을 모델별로 센다. 외부 토크나이저 플러그인 → 제공자 사전 계수 API → 관측 보정 휴리스틱 순으로 적용하고, 어느 경로를 썼는지 `inputBudget.tokenCountSource`와 `exact`에 남긴다.
- 호출 뒤 제공자가 보고한 입력 토큰과 사전 계수를 비교해 `inputBudget.accuracy`에 오차를 기록하고, 다음 추정의 보정 계수로 되돌린다.
- 위험 키워드와 질의어가 모두 없는 조항도 단서·우선 적용·위임 같은 구조 표지와 조항 꼬리 구간을 기준으로 발췌한다. 발췌 창이 겹치면 합치고 남은 예산은 다시 창을 넓히는 데 쓴다.

## 설정

`LLM_CONTEXT_TOKENS`, `LLM_OUTPUT_TOKENS`는 서버의 운영 예산이다. 기본값은 클라우드 경로 32768/3500, Ollama 16384/8192이며 기존 `OLLAMA_NUM_CTX`, `OLLAMA_NUM_PREDICT` 설정을 이어받는다. 이는 모델 제조사가 보장한 최대 용량 목록이 아니므로 실제 선택 모델의 한도에 맞게 설정해야 한다.

`LLM_MODEL_BUDGETS`에는 정확한 `제공자:모델명`을 키로 한 JSON을 넣을 수 있다. 예: `{"ollama:my-local-model":{"contextTokens":16384,"outputTokens":4096}}`. 같은 키에 `"family"`(토크나이저 계열)나 `"tokensPerChar"`(문자군별 계수)를 함께 넣어 계수를 덮어쓸 수 있다. 모델별 항목이 공통 환경변수보다 우선한다. 내부 함수의 명시적 `llmConfig.contextTokens/outputTokens`는 그보다 우선하며 HTTP 요청에 예산 변경 입력은 추가하지 않았다.

## 모델별 토큰 계수

입력 토큰은 아래 순서로 구한다. 앞의 두 경로만 정확한 값이며 `exact:true`로 표시한다.

1. `LLM_TOKENIZER_MODULE`에 지정한 외부 토크나이저 모듈. `countTokens(text, { provider, model })`을 내보내야 한다. 이 저장소는 토크나이저를 의존성으로 포함하지 않으므로 OpenAI 계열을 정확히 세려면 이 자리에 연결해야 한다.
2. 제공자의 사전 계수 API. Anthropic `POST /v1/messages/count_tokens`와 Gemini `models/{model}:countTokens`를 생성 호출과 같은 본문 구성으로 호출한다. OpenAI와 Ollama에는 대응 엔드포인트가 없다.
3. 문자군 휴리스틱. 한글·한자·영문·숫자·공백·기타를 나누어 계열별 토큰/문자 계수를 적용한다. 계열은 `claude`, `o200k`, `cl100k`, `gemini`, `local`, `default`이며 제공자와 모델명으로 고른다. 판별하지 못하면 가장 보수적인 `default`를 쓴다.

계수표는 **측정값이 아니라 예산 편성을 위한 사전값**이다. 대신 호출할 때마다 제공자가 보고한 실제 입력 토큰과 비교해 `provider:model`별 보정 계수를 갱신하고 다음 추정에 적용한다. 보정은 프로세스 수명 동안만 유지하며 표본이 적을 때 과소 추정하지 않도록 평균과 최대 관측치를 함께 쓴다. 프롬프트와 동떨어진 값(0.15배 미만, 6배 초과)은 버린다. 추정 경로에는 `LLM_ESTIMATE_MARGIN`(기본 0.15)의 여유를 더한다.

정확한 계수를 쓰지 못하면 `exact:false`로 남고 실패 사유는 `tokenCountError`에 기록한다. `LLM_EXACT_TOKEN_COUNT=false`로 사전 계수 호출을 끌 수 있고 시간 제한은 `LLM_COUNT_TIMEOUT`(기본 10초)이다. 축소 반복은 동기 추정으로 돌리므로 사전 계수 API 호출은 검토 1건당 최대 2회다.

한글 9,020자 프롬프트에서 이전 방식은 21,998토큰으로 셌고 새 방식은 `claude` 9,579, `o200k` 10,303, `cl100k` 18,380, `local` 14,822, `default` 20,201토큰으로 센다(여유 15% 포함). 이전 방식은 한글 1자를 3토큰으로 취급한 셈이어서 실제로는 들어갈 문서를 불필요하게 잘라냈다. 두 값 모두 실제 모델 토크나이저로 검증한 수치가 아니며, 검증은 `exact` 경로와 `accuracy` 기록이 담당한다.

## 평가 결과

- 회귀 테스트 61개 통과. 실제 프롬프트·출력 한도, 모델별 설정, 과대 질의의 호출 차단, 제공자별 사용량 매핑, 잘린 출력, 가지 조문과 후반 위험 문구, 계열별 계수 구분, 사전 계수 API 사용과 실패 대체, 관측 보정을 검증했다.
- `node test/benchmark/contextRecall.js`는 9종 합성 문서 × 2개 예산(1500/4500자)을 평가한다. [결과 JSON](context-recall-2026-09-21.json)에 성공과 실패, 표식별 신호 유형을 모두 기록했다.
- 표식 26개 중 24개를 회수했다. 같은 예산의 단순 앞부분 발췌는 4개를 회수했다. 신호 유형별로는 위험 키워드 16/16, 구조 표지만 있는 경우 6/6, 표지 없이 위치만으로 덮인 경우 2/2, 아무 신호도 없는 대조군 0/2다.
- 이전 보고서에서 놓쳤던 '키워드 없는 말미 조건'은 두 예산 모두에서 회수한다. 구조 표지(단서·우선 적용·부속 문서·위임)와 조항 꼬리 발췌가 근거이며, 의미를 이해해서가 아니라 조건이 뒤집히는 자리의 문법적 신호와 위치로 찾는다.
- 표지도 키워드도 없고 문서 중간에 있는 문장은 여전히 놓친다(`no-marker-middle-control`). 임베딩 검색, 의미 기반 쟁점 추출, 문서 전수 검토는 구현하지 않았다. 부분 발췌 경고를 유지한다.
- 이번 작업에서도 유료 LLM 생성과 실제 모델의 토큰 계수 측정은 수행하지 않았다. 사전 계수 API 연동과 사용량 매핑은 주입 응답으로 검증했고, 계수표 자체의 오차는 실제 호출에서 `inputBudget.accuracy`로 측정되도록 남겼다. 법령 API는 변경하지 않아 이전 통합 테스트를 반복하지 않았다.

회수 건수는 의도적으로 배치한 합성 표식 기준이며 제품 법률 정확도, 실제 사용자 문서 회수율, 이전 전체 구현 대비 개선율이 아니다.

## 참고한 공식 명세

- [OpenAI 토큰 계수](https://developers.openai.com/api/docs/guides/token-counting): 출력 사용량에는 비가시 토큰도 포함될 수 있다. 사전 추정과 제공자 사용량을 같은 값으로 취급하지 않는다.
- [Ollama Chat API](https://docs.ollama.com/api/chat): `prompt_eval_count`, `eval_count`를 응답에서 읽는다.
- [Gemini GenerateContent](https://ai.google.dev/api/generate-content): 응답의 사용량 메타데이터를 읽고 생각 토큰·전체 토큰을 별도로 보존한다.
- [Anthropic Messages 토큰 계수](https://platform.claude.com/docs/en/build-with-claude/token-counting): `POST /v1/messages/count_tokens`에 생성과 같은 `system`·`messages`를 보내고 `input_tokens`를 읽는다. 모델별 값이므로 생성에 쓸 모델명을 그대로 보낸다.
- [Gemini countTokens](https://ai.google.dev/api/tokens): `models/{model}:countTokens`로 같은 본문의 `totalTokens`를 읽는다.

## 남은 작업

- OpenAI·Ollama의 정확한 입력 토큰 계수. 토크나이저 플러그인 자리는 열어 두었으나 이 저장소에 토크나이저를 포함하지 않았다.
- 실제 유료 호출로 계수표와 보정의 오차 측정. 현재 값은 사전값이며 `inputBudget.accuracy`로만 검증된다.
- 보정 계수의 프로세스 간 유지. 지금은 재시작하면 사라진다.
- 의미 기반 쟁점 회수. 구조 표지가 없는 문장은 임베딩 검색이나 문서 전수 검토가 필요하다.

전체 위임 관계·부칙 적용, 전문가 정답 기반 법리 평가, 브라우저·Word/한글 시각 검증, 외부 공개용 인증은 별도 잔여 과제다.
