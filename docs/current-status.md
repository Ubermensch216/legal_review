# 현재 구현·검증 상태

기준일: 2026-09-24. 이 문서는 저장소의 현재 사용 경로와 검증 범위를 요약한다. 날짜가 붙은 조사·감사·계획 문서의 당시 관찰은 기록으로 남겨 두며, 현재 운영 판단은 이 문서와 [단계형 비교 기록](audit/pipeline-comparison-2026-09-23.md)을 따른다.

## 실행 경로

- 일반 API 검토는 `REVIEW_PIPELINE`을 설정하지 않은 단일 호출(`monolithic`) 경로다. 외부 전문가 질의용 수동 학습 경로는 최초부터 단계형으로 실행해 재사용할 쟁점·요건·공백 구조를 저장한다. 이 경로에서 단계형이 실패하면 단일 호출 결과를 원 검토로 저장하지 않는다. 일반 검토에서 최초 입력이 모델 예산을 넘으면 단계형 경로를 먼저 사용한다.
- 판례·해석례는 공식 검색 목록을 먼저 조회하고, 짧은 목록 정보를 LLM으로 묶음별 선별한 후 통과·불확실 후보의 본문만 조회한다. 명시 인용 후보를 보호하고, 선별기 장애·불완전 응답 시 후보를 보존한다. 목록 판정은 법적 근거가 아니며 공식 본문을 확인한 자료만 인용할 수 있다. 선별 기록은 `meta.evidenceScreening`, 단계형 추가 조사는 `reasoning.diagnostics.research.screening`에 남는다.
- 단계형은 근거 등록부(S0), 쟁점(S1), 조사(S2), 요건 분해(S3), 쟁점별 포섭(S4), 근거 검증(S6), 공백 산출(S7), 종합(S5)을 사용한다. 호출 원장과 구조화된 쟁점·요건 판단을 결과에 저장한다.
- 단계 호출마다 입력 토큰을 사전 검사한다. S1이 넘치면 첨부문서 조각별로 쟁점을 추출해 병합한다. S4는 근거가 한 호출에 다 들어가지 않으면 여러 묶음으로 판단하고, 충돌은 다툼으로 처리한다. 끝내 처리하지 못한 조각·근거는 ID와 함께 `PARTIAL`/검토 필요 사유로 남긴다.
- 로컬 Ollama가 현재 검증 대상 모델이다. OpenAI·Anthropic·Gemini 연결 코드는 유지하지만 2026-09-23 단계형 실측은 `gemma4:e2b`로만 했다. 외부 전문가 질의는 자동 클라우드 호출이 아닌 사용자의 비식별 질의서 반출·답변 반입 경로다.
- 학습 탭은 외부 AI 또는 사람 전문가 답변 출처를 기록하고, 질문별 답변을 승인 카드로 만든다. 외부 질의서에는 법리 공백만 질문으로 싣고 관련 사실·요건·반대 논리·판례 비교·복원한 공식 근거 원문을 함께 제공한다. 내부 근거 ID는 사람이 읽는 표제로 바꾸고, 원문이 누락되거나 저장 당시 근거와 달라졌으면 질의서 생성을 중단한다. 내부 자료 수집·파싱 오류는 별도 보완 항목으로 표시한다. 최종 재검토는 원 검토의 공식 근거 스냅샷·사실·쟁점·요건을 재사용한다. 답변이 연결된 요건만 다시 판단하고 후속 쟁점의 결론을 갱신한 뒤 종합 결과를 만든다. 원 구조나 승인 지식을 재사용할 수 없으면 새 분석으로 대체하지 않고 중단한다. 최신 법령의 재수집·편입, 사건 밖 카드의 임베딩 기반 재사용은 보류다.
- 화면은 기존 4개 검토 탭과 학습 탭을 제공한다. 단계형 결과의 쟁점·요건 표는 검토 초안 안에서 표시된다. 별도 쟁점·요건 탭은 없다.

## 검증된 범위와 전환 판단

`npm test`: **230건 통과, 0건 실패** (2026-09-24, 외부 통신 차단 단위 테스트). 목록 선별·본문 조회·토큰 초과 분할의 단위 테스트를 포함한다. 실서비스 API와 로컬 모델을 통한 변경 후 전체 검토는 아직 재측정하지 않았다. 테스트 통과는 법리 정확도나 보고서의 실무 적합성 보증이 아니다.

실제 API·로컬 모델 소규모 점검: `공유재산` 목록 3건의 목록 선별 호출은 성공했으며, 해당 3건의 상세 조회는 공식 API에서 일치하는 판례가 없다는 응답을 돌려 본문을 확보하지 못했다. 별도 `개인정보` 목록 3건은 같은 상세 조회 경로에서 본문 3건을 확보했다. 따라서 목록 선별 성공과 공식 본문 확보는 별도 상태로 표시해야 한다. 목록 선별의 법적 적합성·누락률과 전체 검토 시간은 아직 측정하지 않았다.

공식 API·로컬 모델로 5개 샘플을 각각 1회 진단 측정했다. 단계형은 5개 모두 파싱하고 규칙 기반 폴백은 없었지만, 사례 02·05의 쟁점은 모두 생략됐다. 사례 04의 인용 존재율은 82%, 기대 조문 재현율은 25%였다. 사례 01의 모델 처리 시간은 단일 호출보다 27% 길었다. 기준선과 단계형 실행 사이 코드 수정이 있어 엄격한 동조건 A/B 비교는 아니다. 상세 수치와 제약은 [비교 기록](audit/pipeline-comparison-2026-09-23.md)에 있다.

현재 단계형은 생략 쟁점을 공식 근거 공백과 `HUMAN_REVIEW_REQUIRED`로 표시하고, 사실 확인 질문을 사용자 경로로 분류한다. 이 수정은 저장 결과의 재계산과 테스트로 확인했으며, 수정 후 실모델 전체 재실행은 아직 하지 않았다. 따라서 단계형 전환 조건(인용·조문 재현율, 처리 시간)을 충족했다고 볼 수 없다.
