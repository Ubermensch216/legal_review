# 현재 구현·검증 상태

기준일: 2026-09-23. 이 문서는 저장소의 현재 사용 경로와 검증 범위를 요약한다. 날짜가 붙은 조사·감사·계획 문서의 당시 관찰은 기록으로 남겨 두며, 현재 운영 판단은 이 문서와 [단계형 비교 기록](audit/pipeline-comparison-2026-09-23.md)을 따른다.

## 실행 경로

- 기본 검토는 `REVIEW_PIPELINE`을 설정하지 않은 단일 호출(`monolithic`) 경로다. `REVIEW_PIPELINE=staged`는 시험용 단계형 경로이며 기본값으로 전환하지 않았다. S1 쟁점 정리에 실패하면 단일 호출로 넘어간다.
- 단계형은 근거 등록부(S0), 쟁점(S1), 조사(S2), 요건 분해(S3), 쟁점별 포섭(S4), 근거 검증(S6), 공백 산출(S7), 종합(S5)을 사용한다. 호출 원장과 구조화된 쟁점·요건 판단을 결과에 저장한다.
- 로컬 Ollama가 현재 검증 대상 모델이다. OpenAI·Anthropic·Gemini 연결 코드는 유지하지만 2026-09-23 단계형 실측은 `gemma4:e2b`로만 했다. 외부 전문가 질의는 자동 클라우드 호출이 아닌 사용자의 비식별 질의서 반출·답변 반입 경로다.
- 학습 탭은 외부 AI 또는 사람 전문가 답변 출처를 기록하고, 질문별 답변을 승인 카드로 만든다. 근거 지문이 같은 사건의 연결 쟁점은 부분 재검토할 수 있다. 새 판례·조문의 공식 API 확인·편입, 사건 밖 카드의 임베딩 기반 재사용은 보류다.
- 화면은 기존 4개 검토 탭과 학습 탭을 제공한다. 단계형 결과의 쟁점·요건 표는 검토 초안 안에서 표시된다. 별도 쟁점·요건 탭은 없다.

## 검증된 범위와 전환 판단

`npm test`: **186건 통과, 0건 실패** (2026-09-23, 외부 통신 차단 단위 테스트). 실서비스 API 계약은 일부 표본만 확인했다. 테스트 통과는 법리 정확도나 보고서의 실무 적합성 보증이 아니다.

공식 API·로컬 모델로 5개 샘플을 각각 1회 진단 측정했다. 단계형은 5개 모두 파싱하고 규칙 기반 폴백은 없었지만, 사례 02·05의 쟁점은 모두 생략됐다. 사례 04의 인용 존재율은 82%, 기대 조문 재현율은 25%였다. 사례 01의 모델 처리 시간은 단일 호출보다 27% 길었다. 기준선과 단계형 실행 사이 코드 수정이 있어 엄격한 동조건 A/B 비교는 아니다. 상세 수치와 제약은 [비교 기록](audit/pipeline-comparison-2026-09-23.md)에 있다.

현재 단계형은 생략 쟁점을 공식 근거 공백과 `HUMAN_REVIEW_REQUIRED`로 표시하고, 사실 확인 질문을 사용자 경로로 분류한다. 이 수정은 저장 결과의 재계산과 테스트로 확인했으며, 수정 후 실모델 전체 재실행은 아직 하지 않았다. 따라서 단계형 전환 조건(인용·조문 재현율, 처리 시간)을 충족했다고 볼 수 없다.
